# 设计说明（公开版）

这份文档说清楚三件事：插件怎么把对话分层压扁、它依赖宿主的哪些约定、以及哪些事它**不做**。
内部开发用的完整规范不对外发布。

- 插件名：`dsh-ebbing-context`
- 宿主：DeepSeek Harness（cordis 插件体系）
- 状态：**尚无一次完整的真机成功运行记录**（安装与验证步骤见 README）

---

## 1. 它解决什么问题

上下文窗口被原始对话填满之后，只有两个选择：截断（信息直接丢），或让模型把旧内容总结掉（信息还在，只是变粗）。

Ebbing Context 做后者，并坚持一条：**摘要正文永远由模型写**。插件只决定"什么时候该压、压哪一段、压完的东西以什么形状留在会话里"。

它不自动压缩，也不替模型判断该压哪几轮。

---

## 2. 分层模型

会话表层被切成四个区，从新到旧：

```
[system] [L3 块] [L2 块] [L1 块] [L0 原文] [当前轮]
```

| 区 | 内容 | 谁产生 |
|---|---|---|
| L0 原文 | 还没被压掉的原始消息 | 用户与模型产生 |
| L1 块 | 一批 L0 原文压成的摘要 | `compress(l0=…)` |
| L2 块 | 一批 L1 块合并成的摘要 | `compress(l1=…)` |
| L3 块 | 一批 L2 块合并，或整个 L3 区合并 | `compress(l2=…)` / `compress(l3=…)` |

层级不存储：每轮从表层节点现算。块头写着它盖住的范围，所以插件没有任何自己的台账。

### 块的形状

```
〔L1｜T16–T19｜ev 4121–4390〕这一块的标题
用户意图：…
模型实际执行：…
运行结论：…
数据：…
（本块写就时，其下是原文区，第一条原文轮次为 T20）
（这块压掉了 3 张图片（事件号 4121、4288、4301））
```

- 第一行是身份：层级、覆盖的轮次、覆盖的事件号、标题。
- 中间四行是摘要骨架，由模型写。
- 尾部两行由插件追加：交界声明（只有 `l0` 产物有）与图片台账（有图片才出现）。

---

## 3. `compress` 的四个键

键就是要压的那一层，产物自动升一层。

| 键 | 压什么 | `to` 写什么 |
|---|---|---|
| `l0` | 原文区最老的一段（整轮整轮地压） | 轮号，如 `T19`，表示压到那轮结束 |
| `l1` | L1 区最老的一块或几块 | 块序号，从 1 起（1 = 该区最老） |
| `l2` | L2 区最老的一块或几块 | 块序号，同上 |
| `l3` | 整个 L3 区压成一块 | **不写** `to` |

`l2` 的产物自成一块落在 L3 区**末尾**；已有的 L3 块原样不动，不拼接。

### 级联

压某一层时，比它浅、且**还能压**的层必须同批一起给：

- 压 `l1` 要同时给 `l0`；压 `l2` 要同时给 `l1`、`l0`；压 `l3` 要同时给 `l2`、`l1`、`l0`
- 某层不足两块、或只剩被保护的内容，就不必给（它已经压不动了）
- 漏层会整批被拒，并告诉你缺哪层

### 保护的边界

- **当前轮永不压**
- **每层的最后一块永不压**——它是这一层与新内容之间的接口
- `keepTurns`（默认 2）：原文区必须留住最后 N 轮，`l0` 的 `to` 最多写到 `当前轮 − N`
- 一次压缩必须比被压掉的内容**更小**，否则整批不写

### 一次压缩写四条记录

```
compaction/start → compaction/summary → user/message(replace) → compaction/end
```

`try/finally` 保证补 `end`：缺它会让该会话此后所有压缩被宿主判为"压缩进行中"而拒绝。

替换范围必须覆盖全部被遮住的节点，否则宿主拒绝。

---

## 4. 它不做的事（设计上的硬立场）

1. **不自动压缩**：只在三类时刻提醒，压不压由模型定
2. **不催 `/compact`**：宿主自带压缩会把分层拍平、原文取不回
3. **不替模型判断**：不给"建议压到哪"，只陈述事实与两端代价
4. **不留孤儿**：只做"成对替换"或"只改 `tool/result` 正文"，从不单点删节点
5. **不写磁盘、不建索引**：所有状态从会话表层现算

---

## 5. 提醒机制

三类条件，任一成立就发一条（每轮最多一条，在本轮收尾时附完整地图）：

| 条件 | 默认 | 说明 |
|---|---|---|
| 占用到线 | `triggerPct = 0.75` | **越线才报一次**；掉回线下再越线才会再报 |
| 又长了 | `notice.growthTokens = 65000` | 自上次提醒后又长了这么多，且至少一层压得动 |
| 某层超配额 | `budget.l1/l2/l3 = 0.10/0.06/0.03` | 该层压得动、且更浅的层也压得动时才报 |

增长那条在"压不动"时会把门槛砍半、基线前移，跨轮反复，直到某次真压得动；提醒发出后模型决定不压，则按 `notice.growthResetPct`（默认 40）重设门槛。任何一次压缩成功都把增长状态清回原额。

超出窗口（宿主报 `CONTEXT_WINDOW_EXCEEDED`）只报一次话，不重试、不自动压缩。

## 6. 配置（17 项）

| 键 | 默认 | 作用 |
|---|---|---|
| `triggerPct` | 0.75 | 占用到多少提醒一次 |
| `keepTurns` | 2 | 原文区必须留住最后几轮（最小 1） |
| `pruneFirst` | true | 压缩前先让宿主剪一次超大的工具返回 |
| `foldCallRecord` | true | 压缩成功后把"调用 + 返回"折成一条短注 |
| `requireSessionQuery` | true | 没装"会话搜索"插件时拒绝压缩（取不回原文就不压） |
| `reservedTokens` | 0 | 额外预留 token |
| `budget.l1/l2/l3` | 0.10 / 0.06 / 0.03 | 每层占可用输入的上限 |
| `segment.l1/l2/l3` | 5000 / 2000 / 5000 | 单个块的正文上限（token） |
| `title.maxTokens` | 50 | 块标题上限 |
| `notice.enabled` | true | 提醒总开关 |
| `notice.growthTokens` | 65000 | 增长提醒门槛 |
| `notice.growthResetPct` | 40 | 不压之后门槛重设到原额的百分比 |
| `notice.notifySubagents` | true | 子代理也参与提醒与轮次标记 |

未知键会被拒绝启动——避免"以为设上了、实际用默认值"。

## 7. 依赖的宿主约定

这些是正确性的前提，都是宿主公开行为：

- 表层节点由 `session.surface.nodes` 给出，派生消息由 `session.deriveMessages()` 给出；节点里可能有无内容的节点（被截断的空消息），插件按节点逐个投影，不假设"节点数 = 消息数"
- `assistant/message` 不能携带 `sourceEventSeqs`；`tool/result` 的替换必须恰好一个节点、只改 `content`
- `agent/pre-step` 在每次请求前派发且会被 `await`；`agent/turn-stopping` 是 serial 派发（**没有** `next`）
- `agent.followup()` 投递的消息会在本轮 `turn/end` 之后开新的一轮
- 轮次编号来自宿主的 `turn/start` 事件（投影坏了会改从日志重建）

宿主版本变化时，最该先复核的就是这一节。

---

## 8. 已知限制

- 并行调用时降级：折叠只把返回正文换成一句确认，摘要正文仍会以参数形式留在上下文里
- 图片无法取回，只按张数记账
- 轮次大纲损坏（日志缺 `turn/start` 或乱序）时该轮报红色错误并停用；`l1`/`l2` 需要大纲才能判
- 空节点、层内块不足两块、压完不更小等情形都有明确拒绝文案，不静默改数据
- 区占用由插件自估（中文 1 字 ≈ 1 token），与宿主计价器不完全一致，会略早提醒

## 9. 目录与开发

- `index.js`：插件入口（工具、提示段、监听器）
- `lib/`：`blocks`（读表层、分层、轮次）、`compress`（校验与落盘）、`callfold`（调用记录折叠）、`map`（地图渲染）、`config`、`tokens`、`log`、`license`、`messages`
- `client.js`：配置页
- `test/`：`node --test` 可跑，覆盖分层、压缩校验、折叠、配置、提醒时序、参数 schema、模块作用域检查
- 提交前：`node --check` 全部文件 + 跑全套测试

完整规则（每条为什么这么定、踩过哪些坑）只存在于维护者本地，不在本仓库。
