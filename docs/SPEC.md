## 1. 一句话

模型自己挑位置、自己写摘要，插件只把四条宿主认识的记录写进会话日志；DSH 的界面、取回链、别的压缩后端都不需要知道我们存在。

## 3. 挂载

- profile 的 `cordis.patch.yml` 里**一行 `insert`**，带完整 `config`；不实现、不替换任何宿主服务。
- 包结构按 `cordis-plugin-development` 的 `host-plugin.md` 办：`package.json` 声明 `dsh.bundle.patch`；`exports` 导出 `.` / `./locale/*.json` / `./icon`；`files` 含 patch、locale、icon、全部运行时文件。`locale/{zh,en}.json` 各带 `meta.title` + `meta.description`；`icon.svg` 是自绘的（同心横条：越靠上越短 = 越老越压缩）。
- `index.js` 只导出 `apply(ctx, config)` + `inject`；所有注册都包在 `ctx.effect()` 里，事件用 `ctx.on()`，由插件作用域负责清理。
- 硬依赖（缺了就不启动，且要给可读错误）：`tools`、`sessions`、`tokenMeter`、`agents`、`sessionProjections`。
- 软依赖（`ctx.get()` 取，缺了降级）：`systemPrompt`（缺则不注入提示段）、`toolResultPruner`（缺则跳过剪枝）、`commands`（缺则不注册命令）。
- **不**注册 message projection（卸载会让旧会话拒绝派生）。台账将来用 state projection 做。
- 推荐同时把宿主的 `compaction-basic` 设成 `auto: false`：它的自动压缩会写八段式摘要把金字塔拍平。

## 4. 表层与四区

发送给模型的消息按位置分四区，从上到下：

```
[system prompt]  [L3 区]  [L2 区]  [L1 区]  [L0 原文区]  [当前轮]
```

- **L3 区**：最顶上的摘要块，可多块；顶多块时最上面的是最新。
- **L2 / L1 区**：各自若干摘要块，越靠上越老（序号 1 = 该区最老）。
- **L0 原文区**：还没被压过的真实对话，按时间顺序。
- **当前轮**：永远不压。

层级不是存下来的，是**算出来的**：一个块的层级 = 它盖住的那些节点里最高层级 + 1（盖住的全是原文 → L1）。

---

## 5. 四个键

`compress` 的参数是四个可选键，**键名 = 要压的那一层**：

| 键 | 压什么 | 产物去哪个区 | `to` 怎么写 |
|---|---|---|---|
| `l0` | L0 原文区的开头一段 | 变成一个 L1 块 | 轮号，如 `T19`（= 宿主写的 `turn 19`） |
| `l1` | L1 区的开头几块 | 变成一个 L2 块 | 该区序号，如 `3` |
| `l2` | L2 区的开头几块 | **追加到最上面那个 L3 块的末尾** | 该区序号 |
| `l3` | 整个 L3 区 | 重写成一块更短的 L3 | 不收 `to`（整区） |

每个键都要给 `title`（中文名词短语，≤ `title.maxTokens`，默认 50）和 `summary`（正文）。

**级联是硬前提**（不是建议）：要给 `l3`，就得同批给 `l2`、`l1`、`l0`；给 `l2` 就得给 `l1`、`l0`；给 `l1` 就得给 `l0`。**只在那些层还有内容时才要求**（某层空了就不要求它）。

---

## 6. `context_map`

每次决定压缩前调一次。返回四段：

1. **总量**：已用 / 窗口 / 百分比 / 是否估算。
2. **四区配额表**：每区已用、上限、百分比；超了标「已超设计容量（只影响提醒，不阻止压缩）」。
3. **块列表**：序号 · 区 · 盖住的轮次 · token · 标题。
4. **可压位置**：每区给出可写的锚点（`T1…Tn` 或 `1…n`），空的区写「暂不可用：该区为空」。

地图带流水号。压缩时若地图比实际旧（`rg` 变了），整批拒绝并回吐新地图，让人重取。

---

## 7. 一次压缩写四条记录

每个子事务，按顺序、**同一段同步代码里**：

1. `compaction/start`（`{compactionId, turn}`）
2. `compaction/summary`（`{compactionId, summary, shadowedRange, shadowedSeqs, shadowedTokenCount, provider, model}` —— 这里的 `summary` 是**未加框**的正文）
3. `user/message`（检查点消息，带 `surfaceOp: {op:'replace', startSeq, endSeq}` 与 `sourceEventSeqs`（含**每一个**被遮蔽节点），`source` 用 `{kind:'compact-checkpoint', compactionId}`）
4. `compaction/end`（`{compactionId, turn}`；出错也要写，带 `error`）

正文加框：`〔标题〕` + `CHECKPOINT_PREAMBLE`（宿主原文逐字节）+ `<compacted-summary>`…`</compacted-summary>` + 取回线索行。

多个键一起给时按**表层位置升序**落盘（先 l3；越靠上的越先写），每个子事务独立 `compactionId`。

## 8. 校验（不通过就整批不写）

| 检查 | 拒绝码 | 说明 |
|---|---|---|
| 地图版本过期 | `E_MAPSTALE` | 回吐新地图 |
| 键/字段不合法 | `E_SHAPE` | 含 `l3` 给 `to`、非 l3 缺 `to`、`title`/`summary` 非字符串、一个键都没给 |
| 级联不完整 | `E_CASCADE` | 说清哪层还有多少内容没压 |
| 锚点解析不到 | `E_ANCHOR` | 提示重取地图 |
| 区间重叠 | `E_OVERLAP` | 同一节点不许被两个子事务盖 |
| 工具调用/结果配对不平衡 | `E_UNBALANCED` | 区间边界不能切开一对 |
| 摘要不比被压内容小 | `E_SMALLER` | 宿主硬约束，给出两侧 token |
| 单块超 `segment.*` | `E_TOOLONG` | 给出实测值与上限 |
| 标题超 `title.maxTokens` | `E_TITLELEN` | |
| 会话搜索工具缺失 | `E_NOSEARCH` | 直接报错，不执行任何写入 |

**没有压缩比门槛**（已整套取消，不鼓励模型追求倍数）。

## 9. 提醒

插件往对话尾部追加文字，三种触发，互相独立：

| 触发 | 频率 | 文案要点 |
|---|---|---|
| 占用 ≥ `triggerPct`（0.75） | 每轮一条（同一轮多步只发一条） | 命令式：必须压缩；附当前地图；第二次起因"上次压完仍高于线"换说法 |
| 自上次提醒后又长了 `notice.growthTokens`（65000） | 每触发一次发一条 | |
| 某层区超 `budget.*` | 每层首次越线发一条，回落复位 | 说清前提：超的是哪区、要压就得连下面几层一起压 |

- 提醒只是催，**不保证模型会压**。
- 掉到 `triggerPct` 以下不重置"已经提醒过"的记录，下一轮达到线继续提醒（没有滞回）。

---

## 10. 超限

`agent/request-error` 命中 `CONTEXT_WINDOW_EXCEEDED_CODE` 时：先 `ctx.goals.disarm(agent)` 摘掉自动续作权限，再追加一句面向人的通知（建议手动 `/compact`，或让别的 agent 在场外压）。**不自动压缩、不重试、不改写历史。** 非本码立即 `next()`。

---

## 11. 取回

压缩掉的原文仍在会话日志里。取回**全部委托宿主**：`session_event_search`（`surfaces:["shadowed"]`）+ `session_event_read` 按事件号读原文。插件自己不实现取回工具。

因此：启动时检查这两个工具在不在；不在就两个工具都返回"请开启 DSH 的实验性插件：会话搜索"，且不做任何写入。

---

## 12. 配置默认值

```
budget:   { l1: 0.10, l2: 0.06, l3: 0.03 }        // 窗口比例
segment:  { l1: 5000, l2: 2000, l3: 5000 }        // 单块正文上限（token）
title:    { maxTokens: 50, lang: 'zh' }
triggerPct: 0.75
notice:   { enabled: true, growthTokens: 65000 }
requireSessionQuery: true
pruneFirst: true                                   // 压缩前先剪巨型工具结果
```

长度一律用**插件自带的估算器**（中日韩 1 字=1 token，其他非 ASCII 1，ASCII 数字 3 位=1，ASCII 其他 4 个=1），不用宿主的 `CHARS_PER_TOKEN=4`——它对中文低估约 4 倍。

---

## 13. `compress` 的处理顺序

1. 会话搜索闸门 → 2. `pruneFirst`：`ctx.get('toolResultPruner')?.pruneSession(session)`（报 `prunedChars`）→ 3. 读区与算层级 → 4. 填表格式校验 → 5. 级联校验 → 6. 每个键解析 `to` 成 seq → 7. 区间不相交 → 8. 配对平衡 → 9. 长度/标题校验 → 10. 按表层位置升序逐个子事务落盘（`try/finally` 保证补 `end`）→ 11. 返回结果（每个子事务的块位置、盖掉的条数、省下的 token，以及总量）。

## 16. 卸载之后会留下什么

结论：**可以无损卸载，有三种残留，但都不会让会话坏掉**。

插件注册的东西全部挂在 `ctx.effect` / `ctx.on` 上：两个工具、一段系统提示、两个事件监听、一个 `/context-status` 命令。卸载即撤销，不留任何挂在宿主上的钩子。

**不注册 message projection、不注册 state projection、不写磁盘状态**——这是卸载安全的关键。宿主的规则是：缺少 message projection 会让旧会话拒绝继续派生，所以那类东西一旦注册就绑死了会话生命周期。我们不碰它。

留在会话里的三种东西：

| 残留 | 形态 | 卸载后表现 |
|---|---|---|
| 压缩块 | 一条普通 `user/message`，正文第一行自带 `〔L1｜T16–T19｜ev …〕` 元信息 | 照常显示、照常被模型读到；没有插件也能看懂它是压缩结果 |
| 四条记录 | `compaction/start` / `summary` / `end` + 替换消息 | 都是宿主本来就认识的类型；未配对只会影响宿主的压缩锁 |
| 提醒与超限提示 | 普通 `user/message` | 就是一句历史消息，无害 |

**唯一的真实风险**：条写在同一段同步代码里，中间被进程强杀会留下未配对的 `compaction/start`。宿主据此认为"会话里已经有压缩在跑"，此后 `/compact` 与宿主自动压缩都会被拒（报 `compaction already in progress`），直到这次会话生命周期出现新的 `session/end-seed`（重启会话即可）。普通异常走 `try/finally` 已经覆盖，剩下的只有强杀这一种。

## 17. 插件自己的记录：没有任何会单调增长的东西

| 记录 | 存在哪 | 是否随会话增长 |
|---|---|---|
| 压缩块的层级 / 覆盖轮次 / 事件号 | **写在块正文第一行**，不是我们的表 | 否（块数受 `budget.*` 约束，顶层最多一块） |
| 轮号 → seq | 读宿主 `turnOutline` 投影，只读不写 | 否（宿主自己的账） |
| 提醒去重（`reminded`） | 进程内 Map，按 agent 存 | 否（`agent/disposed` 时删除） |
| 超限去重（`overflowSaid`） | 同上 | 否（同上） |
| 运行日志 | `<DSH_HOME>/logs/infinity-context.log` | 是，所以**按大小滚动**：2 MiB × 2 份，单条 ≤4 KiB，写失败静默 |
| 配置校验状态（`Config`） | 未实现 | — |

设计上刻意不用 projection 台账：块自己带着元信息，插件随时可以从表层重建全部状态，**重启、换机、卸载后的行为完全一致**。

## 18. 修订：v1.1（按独立只读审计修正，2026-10-28）

审计方指出 20 条偏离，本节记录**已改**与**仍已知**。第 1–17 节凡是与之冲突的，以本节为准。

### 已改
1. **l2 通路**：建表时区间只取 L2 区，落盘时按当前表层往前吃掉 L3 区（`absorbTopL3`）。同批带 l3 时不再撞区间重叠。
2. **旧 L3 正文不再丢**：产物正文 = L3 区所有块的正文（按表层顺序）+ 新段落，整批一次性写进新块；不再有"算出来却没人读"的变量。
3. **工具调用配对校验（`E_UNBALANCED` 落地）**：区间内开着的调用必须在区间内有结果，区间内的结果必须有对应调用；不满足整批拒绝并说明。
4. **表层与派生消息对齐校验**：`deriveMessages().length !== surface.nodes.length` 时响亮拒绝（宿主会跳过派生为空的节点）。
5. **不再调用 `session.eventAt`**（官方弃用）：区间计价改用 `deriveMessages()` 的下标。
6. **收益校验算上取回线索行**：`afterOwn = 估算(块正文 + 线索行)`，不再出现"校验通过但写出来更大"。
7. **地图序号 = 区内序号**，与 `to` 同义；L3 区标注"1 = 最上面（最新）"；可压位置只列已结束轮次的 T 锚点。
8. **区配额与地图占用改用自研估算器**（中文 1 字 1 token），不再用宿主 4 字 1 token 的口径。
9. **级联校验按"可压内容"算**：当前轮原文不算可压内容，否则永远欠一层。
10. **会话搜索闸门查两个工具**（`session_event_read` 与 `session_event_search`）。
11. **删掉 `stopPct`**（配置、patch、README），提醒回落即复位，没有滞回。
12. **工具执行兜底**：意外异常转成一句中文原因，不把 JS 堆栈甩给模型。

### 仍已知（不装不知道，或本版故意不做）
- **`E_MAPSTALE`（地图流水号）未实现**：锚点都按"当前表层"解析，解析不到就报错重取；但"拿着旧地图按区内序号压缩"仍可能压到非预期的块。要做需要先在规范里定死流水号字段位置。
- **块层级取自块头**：块头缺失或来自宿主 `compaction-basic` 时按 L1 归类，不重算。
- **强杀残留**：`compaction/start` 到 `end` 之间被强杀仍会留下未配对开始（微秒级窗口），宿主会拒后续压缩直到会话重启。
- **真机未验证**：以上全部只在假宿主上跑过。
