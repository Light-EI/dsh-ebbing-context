# 设计说明（公开版）

这份文档说清楚三件事：插件怎么把对话分层压扁、它依赖宿主的哪些约定、以及哪些事它**不做**。
内部开发用的完整规范不对外发布。

- 插件名：`dsh-ebbing-context`
- 宿主：DeepSeek Harness（cordis 插件体系）
- 状态：真机上跑通过压缩；没有可复现的验证记录（安装与验证步骤见 README）

---

## 1. 它解决什么问题

上下文窗口被原始对话填满之后，只有两个选择：截断（信息直接丢），或让模型把旧内容总结掉（信息还在，只是变粗）。

Ebbing Context 做后者，并坚持一条：**摘要正文永远由模型写**。插件只决定"什么时候该压、压哪一段、压完的东西以什么形状留在会话里"。

它不自动压缩，也不替模型判断该压哪几轮。

---

## 2. 分层模型

模型每轮看到的上下文是一条线性的消息列表。本插件把它分成四个区：

```
[系统提示] [L3] [L2] [L1] [L0 原文] [当前轮]
```

- **L0**：还没有被压缩的原始对话，按轮次排列。
- **L1 / L2 / L3**：压缩产生的块，层级越高越浓缩。
- 当前轮永远完整，且永远不参与压缩。

**块的层级不存，算出来**：一个块盖住的那些节点里最高层级 + 1。块自己的身份写在正文第一行：

```
〔L1｜T16–T19｜ev 4121–4390〕标题
```

层级、覆盖的轮次、覆盖的事件号范围，以及一行标题。插件因此**不维护任何台账**：任何时候都能从会话表层重建全部状态，重启、换机、导出再导入，行为完全一致。

模型看不见轮号（API 载荷是纯内容），所以插件在每轮收尾写一条可见的路标：`〔轮次标记〕下一轮 T{N+1}`。定位时以这条路标为准；宿主自己的轮次大纲只用来交叉校验，两者对不上就报错。压 `l0` 时，块末再写一句交界声明，说明"这块下面是哪一轮开始的原文"。

---

## 3. `compress` 工具

模型调用 `compress`，参数是**要压的那一层**：

| 键 | 压什么 | 产物 | `to` |
|---|---|---|---|
| `l0` | L0 区开头的一段（到 `to` 那轮结束，整轮） | 一个 L1 块 | 轮号，如 `T19` |
| `l1` | L1 区开头的几块 | 一个 L2 块 | 该区序号，最多到「块数 − 1」 |
| `l2` | L2 区开头的几块 | 自成一块，落在 L3 区末尾；旧 L3 块原样不动 | 该区序号，同样「块数 − 1」 |
| `l3` | 整个 L3 区 | 重写成一块更短的 L3 | 不接受 `to` |

每个键都要给 `title`（短标题）与 `summary`（摘要正文）。

**级联是硬前提**：要给深层，就必须同批把比它浅、且**还能压**的层一起给——一次提交只断一次前缀缓存。浅层没得压时（不足 2 块、或只剩被保护的轮次）不用给。

**三条保护**：当前轮永不压；每层最后一块不压（它是这一层与新内容的接口，`l3` 例外）；原文区必须留住最后 `keepTurns` 轮（默认 2）。

**唯一硬指标**：压完必须比被压掉的内容小，否则整批拒绝并给出两侧实际值。没有"压到多少比例"的目标——那只会鼓励过度压缩。

摘要固定四行：

1. **用户意图**——用户要你做什么、为什么，连他明确给的约束与纠正。
2. **模型实际执行**——真正做了哪些动作；没做成的、失败过的尝试也要写，连同原因。
3. **运行结论**——最后成了什么、没成什么；产出是文件、报告、图片这类附件时，把路径或地址写全。
4. **数据**——还要继续用的具体数值、标识符、路径与命令。

不允许"如上所述"式的跨块引用；更早的摘要里的内容，只有在该块不会被这次一起压掉时才可省略。

---

## 4. 会话里写什么

一次压缩按顺序写四条会话事件：

1. `compaction/start`
2. `compaction/summary`（摘要正文与统计）
3. 一条 `user/message`，以 `surfaceOp: replace` 覆盖被压缩的全部节点
4. `compaction/end`

**为什么是这四条**：宿主只认这一套压缩协议；`end` 是配对凭据，缺了它之后所有压缩都会被判 `busy`。所以写 `start` 之后无论成败都必须补 `end`。

**为什么用 `user/message` 承载块**：宿主不允许 `assistant/message` 携带来源列表，而替换任何节点都必须列出被遮的全部节点。两者一夹，只有 `user/message` 能当替换产物。块正文自带身份（见 §2），所以不依赖任何额外记录。

原文没有消失：被压掉的节点在会话日志里仍然存在，可以按事件号取回（见 §7）。

压缩成功后，插件会把"这次调用 + 它自己的返回"两条消息换成一条短注（里面包含刷新后的地图）。这是为了省掉摘要正文在工具参数里的第二份拷贝；并行调用时整段替换会连坐兄弟调用，所以那时干脆不折。这件事只在下一次请求发出之前做——已经进过请求的节点不再改写。

---

## 5. `context_map` 工具

一份预算有限的索引：块表（序号 / 覆盖轮次 / 每块 token / 标题）、每层的压力与配额、可压区间、以及压缩须知。

它**不是内容替代品**：模型靠块标题与块大小决定"并哪几块"，靠压力判断"压完会不会更大"。地图在三个时刻必须出现——提醒、拒绝回执、成功回执——否则模型无从判断错在哪、为什么错。

地图只陈述事实与两端代价，不给"建议压到几"。

---

## 6. 提醒

插件在后台看用量，但**只在真的压得动时**才提醒：叫醒了却压不动，等于白烧一次请求。

三个触发：

1. 用量到 `triggerPct`（默认 75%），只在**越线**时提醒一次；掉回线下再越线会再提醒。
2. 自上次提醒后又长了 `notice.growthTokens`（默认 65000）。
3. 某个区超过配额的第一次。

提醒在**本轮收尾时**投递，并且会直接把模型叫醒写一轮——不是塞进历史等用户下次说话。提醒里带完整地图，并明确写着"这一轮允许什么都不压"。

提醒、轮次标记、折叠注记的正文都自报身份，界面上显示为「插件状态更新」卡片，不会混成用户发言。

---

## 7. 超窗口与取回

请求真的超窗口时，插件**不自动压缩、不重试**：摘掉自动续作权限，留一条面向人的说明（先把输出预留调小、或换更大的窗口），要不要用宿主自带的压缩由用户决定。

取回原文全部委托宿主的「会话搜索」能力：按事件号搜索与读取。所以本插件不实现自己的取回通道；没装那个能力时，`compress` 与 `context_map` 会直接停用并说明原因——取不回来就不让压。

## 8. 配置

17 个配置项，全部可在「插件」面板里改，保存即生效：

| 组 | 项 | 默认 | 含义 |
|---|---|---|---|
| 配额 | `budget.l1` / `l2` / `l3` | 0.10 / 0.06 / 0.03 | 每层占可用输入预算的比例，超了提醒 |
| 单块上限 | `segment.l1` / `l2` / `l3` | 5000 / 2000 / 5000 | 产物层的单块正文上限（token） |
| 标题 | `title.maxTokens` | 50 | 块标题上限 |
| 提醒 | `notice.enabled` | true | 总开关 |
| 提醒 | `notice.growthTokens` | 65000 | 又长多少再提醒 |
| 提醒 | `notice.growthResetPct` | 40 | 提醒发了但模型决定不压时，门槛重设到原额的百分之几 |
| 提醒 | `notice.notifySubagents` | true | 子代理是否也参与（标记与提醒） |
| 触发 | `triggerPct` | 0.75 | 到线提醒 |
| 保护 | `keepTurns` | 2 | 原文区保留的最后 N 轮（必须 ≥ 1） |
| 行为 | `pruneFirst` | true | 每次压缩前先把超大的工具返回剪短一次 |
| 行为 | `foldCallRecord` | true | 压缩成功后把"调用 + 返回"折成一句短注 |
| 行为 | `requireSessionQuery` | true | 没有「会话搜索」就停用两个工具 |
| 行为 | `reservedTokens` | 0 | 读不到路由输出上限时的兜底预留 |

## 9. 安装与验证

两种方式（详见 README）：用 `dsh plugin add` 装，或在 profile 的 `cordis.patch.yml` 里加一行指向 `index.js`。**只把目录拷进去而不加那一行，插件不会启动**，而且宿主只会写一行日志。

装完确认：插件面板里能看到「Ebbing Context」，两个工具（`compress`、`context_map`）与命令 `/context-status` 都在。

## 10. 已知限制

- **不自动压缩**：不提醒就不会压。
- **并行调用时不折叠**：`compress` 与别的工具并行发出时，调用记录无法整段替换（会连坐兄弟调用），返回正文也不改写（那会让已经发出的前缀缓存作废）。摘要正文会以参数形式留在上下文里，直到下一次覆盖它的压缩。所以提示里明确要求单独发。
- **只折叠还没被发出去的那一对**：折叠必须紧跟在工具返回之后、下一次请求构造之前完成；一旦这一步错过（别的插件先写了节点、或那一轮异常收场），这条就不再折——改写一条已经进过请求的节点会让它之后的缓存全部重算，比多留一份摘要贵得多。
- **图片只记数**：块正文记"这块压掉了 N 张图片（事件号 …）"，原图本身由宿主按它自己的策略离线化。
- **轮次大纲损坏时停用**：宿主报出的轮次无法对齐（缺轮或乱序）时，插件在每轮开头报红色错误并停用本次对话，避免切错边界。"当前轮还没有节点"不算损坏。
- **没有可复现的真机记录**：功能都有单测，真机上也跑通过，但当时的地图、日志与压缩前后对比没有归档，复现不了。
