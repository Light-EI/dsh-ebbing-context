## 1. 第一条真机反馈之后，哪些改动真的改了功能逻辑

第一条真机反馈是 0.1.0 装上去报的 `Invalid schema for function 'compress': true is not of type "array"`（2026-10-30）。从那一刻到现在的全部提交逐条过了一遍：

| 提交 | 内容 | 改功能逻辑？ |
|---|---|---|
| `2944ee6` | 嵌套块参数改用 `required` 数组（修 schema 崩溃） | 否，修 bug |
| `0c47bbf` `2853923` | 测试与 SPEC §27 | 否 |
| `2d45f06` `f815e6d` | 面板文案（本机细节、配置入口、整层口径、不替模型下命令、L3 旧块） | 否，纯文案 |
| **`ad6ddd1`** | **pruner 常开：`maybePrune` 挂在 `agent/pre-step`** | **是（已于 `m13359` 裁定回滚）** |

**结论：只有一条。** 其余全是 bug 修复、测试、文案与文档。

### 1.1 那一条：先改开、后按裁定回滚

- **当时改成了什么**：每次 `agent/pre-step` 扫尾部 12 个节点，有 `tool/result` 文本超过 pruner 的 `thresholdChars`（默认 8192）就调 `pruneSession`。
- **为什么回滚（用户 m13359 选 A）**：
  1. **宿主的设计是"剪枝 = 压缩的前置步骤"**，不是常驻清洁工：`compaction-basic` 只在 pressure 越过阈值（`basic.index.js:942-951`，剪完若已低于阈值连压缩都不做）与 context-overflow 两处调它。
  2. **剪枝是无条件的，取回是有条件的**：我们默认 `requireSessionQuery: true`，没装会话搜索时两个工具直接停用，但剪枝照剪——被削掉的中间段既不在上下文、也不一定取得回。宿主剪枝时后面总跟着一次摘要，内容还有去处。
  3. **时点越权**：宿主把"内容被削"的风险限定在已决定压缩的那一刻；常开会在模型正要引用某段刚读到的内容时把它削掉。
- **回滚后**：只有 `compress` 里剪一次（`plugin/lib/compress.js:75-84`），与宿主同构。回归断言 `plugin/test/prestep.test.mjs` 的「pre-step 不剪枝」钉住这件事——`maybePrune` 已删，别再挂回去。
- **那次改动顺带的收益没了**：关掉宿主 `auto` 后，单个巨型返回会原样留到模型决定压缩；兜底是 75% 提醒 + 压缩前剪枝。

## 2. 宿主接口：这些约束踩了就是 400 或整轮失败

- **工具参数 schema**：嵌套对象里**不许**写 `required: true`（布尔）。宿主只把**顶层**属性的布尔 `required` 折成父级数组，嵌套层原样透传 → OpenAI 兼容线直接拒整个请求。一律写 `required: ['a','b']`。宿主白名单：`type/oneOf/properties/required/additionalProperties/items/enum/const` + `description/title/default/examples`。**单测全绿也发现不了**，只有 provider 会拒。
- **表层替换三条**（`ref/upstream/session-surface.ts`）：① `assistant/message` 不能带 `sourceEventSeqs`（想改它只能整条换成 `user/message`）；② `tool/result` 可替换但必须**恰好一个节点**、原本就是 `tool/result`、除 `content` 外**逐字段相同**；③ `sourceEventSeqs` 必须覆盖全部被遮节点，否则拒。
- **孤儿不清洗**：请求消息就是逐节点投影，没有配对修复。切分只许落在**整轮边界**；折叠只许**成对**替换。
- **`agent/pre-step` / `agent/turn-stopping` / `agent/request-error` 都不兜异常**：handler 里抛出去会被 `kick()` 静默吞掉（表现为"整轮不发请求"）。三个 handler 全部整段 try/catch，`return next()` 放在 try 之外。顺带：这三个事件的载荷都被 `agentEvents` 注入了 `agent`（就是那个 AgentLoop 实例），所以 `agent.followup()` 可直接调。
- **编译期互斥**：`compaction/start` 写了不关，宿主 `assertCompactionInactive` 会一直 `ManualCompactionError("busy")`，此后所有压缩都被拒。`try/finally` 补 `end`，补写失败要在回执里明说"建议开新会话"。
- **宿主自带自动压缩默认开**（`compaction-basic` 的 `auto`，80% 触发）：它会把多层摘要拍平。插件不能替用户改宿主配置，只能在面板里说清"关的是什么"。
- **pruner 只碰 `tool/result`**：块与摘要剪不到；阈值 8192 / 头 4096 / 尾 1024 是宿主默认值，可由宿主配置改，所以代码里要读 `pruner.config.thresholdChars` 而不是写死。

## 3. 我们自己的坑（设计层，容易第二轮再犯）

- **许可证与 `replaceGeneration`**：任何原位替换（折叠、剪枝）都会让它上涨。谁替换谁 `restate()`，否则模型手里的地图被判过期 → 多一次拒绝，用户白花 token。
- **不靠"消息数 == 节点数"判断对齐**：宿主会跳过空消息（`max_tokens` 截断的空助手消息、空注入）。用 `session.log[seq]` + `deriveEventMessage(event)` 逐节点投影（`deriveExactly`）；拿不到精确映射时才退回整轮边界，且要如实说明"只能整轮压"。
- **块头轮号是写死时的快照**，不重算；块一旦被吸收，范围由新块继承。所以块头写错会一直传下去。
- **折叠只能在 `agent/pre-step`**：工具结果落盘后、下一次请求构造前；那一刻调用与返回必然相邻。失败回执只折地图、错误原因逐字留。
- **并行调用不整段折**：同一条助手消息里有兄弟调用时，整段替换会删掉兄弟、留下孤儿 → 400。只收紧自己那条返回。
- **文案不许替模型下命令**：不写"拆成两次"（次数是我们猜的）、不写"写短一点"（诱导删内容降质量）、不写"建议手动 /compact"（会把用户逼去毁掉分层）。
- **不许拿"省 token"改用户拍过的账**：提醒里附完整地图（`m10951`）、拒绝回执附错误+地图（`m11021`）、提醒在轮末叫醒（`m10065`）——这三条是 §26 的取舍，动了要用户点头。
- **「还能压」与「还有内容」是两回事**：级联判据必须用"这层还能压"（`canCompressZone`），否则某层只剩一块时整批永远过不去。

## 4. 排查顺序（出问题先看哪）

1. **先看 `infinity-context.log`**（同名日志已随改名变成 `ebbing-context.log`）：`pre-step` / `turn-stopping` / `fold-call-record*` / `prune` / `overflow` 每个动作都留一条。
2. **整轮不回复、也不报错** → handler 里抛了异常被吞。查最近改过的事件回调有没有包 try/catch、`return next()` 是否在 try 外。
3. **接二连三的 400** → 表层出现孤儿（切分切在一对中间）或非法替换（改了 `assistant/message`、多节点替换）。查压缩区间端点是否落在整轮边界。
4. **一直"压不动"** → 先看 `/context-status`：ambiguous（无精确映射）、大纲故障、级联缺层、最后一块、keepTurns。四种各有不同措辞，别混着猜。
5. **提醒不响** → 占用读数（`tokenMeter.measure` / 投影）、`notice.enabled`、是否处在被叫醒的那一轮（同一轮不再登记第二条）。
6. **地图过期** → 有人替换了表层却没 `restate`。
7. **面板空白/输入框全空** → `form.state` 快照是否为 `ready`（插件没启动时 `form` 为 undefined，页面会先显示"正在读取配置…"）。

## 5. 工具与环境（Windows 侧，反复踩）

- **改文件用 `edit`/`write`，不要用 PowerShell 的 `-replace` 做批量改写中文**：编码与转义会让内容悄悄变形（`\r` 被当转义吞掉过一个字母）。
- **CRLF 警告**：`git commit` 时常出现 `CRLF will be replaced by LF`，无害，别去改 `.gitattributes` 折腾。
- **解 asar**：仓库里有 `ref/tools/asar-tool.js`（`extract <asar> <innerPath> <dest>`），**不要自己写头部解析**——两次手动解析都读错偏移，输出刷屏。
- **推送 GitHub**：本机 Schannel 拿不到凭据，`git push` 会报 `schannel: AcquireCredentialsHandle failed`。用 `gh auth token` + base64 `x-access-token` + `-c http.https://github.com/.sslBackend=openssl -c http.sslVerify=false`。
- **沙箱**：`git filter-branch` 之类的 `sh` 调用会被拦（`couldn't create signal pipe`），改用"reset 到父提交 + 重放提交"。
- **提交前**：`node --check` 全部 `plugin/**/*.js`，再跑七个测试文件。
