# 第一部分：机制报告

## 1. 它到底在改什么

DSH 把对话记成一份**只追加的日志**。模型每次看到的不是整份日志，而是日志的一个"投影"，叫**表层**：一份按模型可见顺序排的节点列表。每个节点指向日志里的某条记录。

我们做的事只有一件：**往日志里追加几条宿主本来就认识的记录，让表层上的一段旧对话消失、换成一段摘要**。不改请求、不拦截流量、不装代理、不实现宿主的压缩服务。

这么做的直接好处：DSH 自带的界面、重启恢复、会话检索全都无差别认这些记录——因为它们就是宿主自己在用的那套格式。

## 2. 四区三层长什么样

模型看到的顺序永远是这样：

```
系统提示 │ L3 │ L2 块… │ L1 块… │ 原文 │ 当前这一轮
```

- **原文区（L0）**：还没被压过的真实对话。最新、最细。
- **L1 块**：由一段原文压出来的摘要。盖住的原文从表层消失，但留在日志里。
- **L2 块**：由若干个 L1 块合并压出来的摘要。
- **L3 区**：最上层，可以有多块；它是"最老的结论"存放处。

越靠左越老、越短；越靠右越新、越细。压得越深，覆盖的时间跨度越大。

## 3. 四个键各干什么

`compress` 工具接受四个键，**键名 = 要压的那一层**：

| 键 | 把什么压掉 | 产物成为 |
|---|---|---|
| `l0` | 原文区最旧的一段 | 一个新的 L1 块 |
| `l1` | L1 区最老的前 N 块 | 一个新的 L2 块 |
| `l2` | L2 区最老的前 N 块 **+ 旧 L3** | 一个新的 L3 块（新正文接在旧 L3 后面） |
| `l3` | 整个 L3 区 | 压成一块（唯一不写 `to` 的键） |

**级联前提（硬校验）**：压第 n 层，比它浅的、还有内容的层必须同时压。想只动 `l2` 会被直接拒绝，并告诉你还差哪几层、各剩多少。

`to` 怎么写：`l0` 写轮锚点（`T19`，就是宿主自己写在上下文里的"preparing turn 19"那个 19）；`l1`/`l2` 写该区从 1 起的块序号（1 = 最老的）；`l3` 不写。

填表按时间线：`l3 → l2 → l1 → l0`，跟它们覆盖的对话时间顺序一致。

## 4. 一次压缩在日志里写下什么

每个子事务固定四条记录，顺序不能乱：

```
compaction/start      {compactionId, turn}
compaction/summary    {summary 正文, shadowedSeqs（被压掉的全部节点）, shadowedTokenCount, …}
user/message          ← 摘要块本体，带"替换"操作：用它顶掉 shadowedSeqs 那一段
compaction/end        {compactionId, turn}
```

这四条是宿主的**标准格式**，宿主自己的压缩写的是同样四条（只是摘要正文由它自己调模型生成，我们由模型直接写进工具参数）。

`start` 与 `end` 必须成对：留下未配对的 `start`，这条会话此后任何压缩都会被判"已有一笔在途"而拒绝——所以写入失败时必须补一条带 `error` 的 `end`，代码里是 `try/finally` 语义的兜底。

## 5. 层级为什么不存盘

块的身份靠两样东西就能推出来，不需要任何额外记录：

- 这块是不是压缩块：看它 `source.kind === 'compact-checkpoint'`；
- 它盖住了谁：看对应的 `compaction/summary` 里的 `shadowedSeqs`。

层级 = **被它盖住的东西里最高的层级 + 1**（封顶 3）。盖的全是原文 → L1；盖的全是 L1 块 → L2；盖到了 L2/L3 块 → L3。

所以：**零新增持久化格式**。插件被停用、被卸载、DSH 升级，已经写下的块照样是普通消息，照样工作；重新装回来也能从日志算回原样。

## 6. 原文去哪了、怎么取回

原文**没有被删除**，它还在日志里；表层上被摘要顶替了，模型看不到了。

取回依赖宿主的实验性插件「会话搜索」：它能把事件分成"当前 / 被折叠 / 只在日志里"三态，并按事件编号读出**完整的原始记录**。所以本插件不再自己造取回工具，只在两块地方做提示：

1. 每个压缩块正文末尾一行：「这块压掉了 N 条消息（事件号 a–b）。需要原文时用会话搜索按事件号查看。」
2. 系统提示里一句正面说明：「压掉的原文不会消失，需要细节时可以取回。」

如果「会话搜索」没开，`context_map` 与 `compress` 都会直接拒绝并说明要开哪个插件——不静默降级，否则模型会以为还能取回。

## 7. 什么时候提醒、提醒说什么

三个**独立**触发条件，任一满足就发一条（同一轮多步只发一条）：

| 条件 | 默认值 | 说明 |
|---|---|---|
| 占用到线 | 75% | 每轮一条 |
| 又长了 | 65000 token | 总量没到线时这条会先叫 |
| 某层区超容量 | 10% / 6% / 3% | 每层各自首次越线提醒，回落才复位 |

提醒里**直接带一张当前地图**（省掉模型单独调一次地图的往返），并明确要求：收到提醒的那一轮必须真的调用压缩，回一句"我来压缩"不算；要从最上面还有内容的那一层开始、把下面几层一起压掉。

跌到 75% 以下（`stopPct`，可单独设）就清空全部提醒状态。

## 8. 上下文超限时干什么

**只报一句，什么都不自动做**：「上下文超限。建议手动 `/compact`，或者让另一个 agent 在场外帮你压完把结论带回来。」同时停掉自动续作（避免它自己再撞一次）。

不自动压缩、不重试、不改写历史。理由是自动化在"已经超了"这一刻最容易做出不可逆的事，而那时候最该做的是让人知道。

## 9. 与宿主自带压缩的关系

- 我们不实现宿主的压缩服务，也不改动它的配置行。
- 宿主的自动压缩开着时，它会在压力到线时自己压一段、产出一个八段式英文摘要——那会**把金字塔拍平**（它的摘要会吃掉我们堆的块）。所以推荐把它设成 `auto: false`，只保留手动 `/compact` 作为兜底。
- 手动 `/compact` 与我们的插件互不干扰：它走它自己的后端，我们走我们自己的写入。

## 10. 成本账

- **每轮固定开销**：系统提示约 530 token + 两个工具的定义（名称、说明、参数 schema）约 900 token。合计约 1,400 token，长期在场。
- **一次压缩**：一次工具调用（模型写四段摘要），加一次地图（约 350 token）。摘要本身的那次调用是本来就省下来的钱，不算额外成本。
- **缓存**：压缩必然打断一次前缀缓存（断点在最靠前被改动的位置）；把四层攒在一次调用里压，只断一次。这就是"级联不是可选项"的经济理由——只压深层、不压浅层，账单一样要付，省下的却很少。

## 2. 阶段一：离线可测（不装插件，现在就能做）

用合成事件喂给核心逻辑，不需要真会话：

1. **层级推导**：造几种表层——全原文、有 L1 块、L1 上面叠 L2、两个 L3 并列——断言推出来的层级符合预期。
2. **锚点解析**：`T19` 找不到时报什么、序号越界时报什么、序号 1 = 最老是否成立。
3. **填表校验**：六种畸形入参的报错文案（已在冒烟里跑过，补成断言）。
4. **级联校验**：只给 `l2` 且浅层非空时必须被拒；浅层为空时必须放行。
5. **落盘顺序**：假会话记录 `append` 调用序列，断言每个子事务是 `start → summary → replace → end`，且多个子事务按表层位置升序。
6. **失败补 end**：让第二次 append 抛错，断言仍然写了带 `error` 的 `end`。

这一段的验收标准：测试脚本能一次跑完、全绿、覆盖上面六项。

## 3. 阶段二：真机最小闭环（**需要你批准安装**）

约束仍在：不安装任何东西，所以这一步停下等你点头。

装法（最小侵入）：把 `plugin/` 放进插件目录 → 用面板的"安装 bundle"指到这个目录 → 它在 profile 的 Loader 行列表里插一行。不改任何现有行、不碰宿主安装目录。

装完第一步只做一件事：让它把地图打出来，确认四区划分与"可压位置"跟真会话对得上。

## 5. 阶段四：加固

1. `/context-status` 只读命令：让人随时问"现在几层、各占多少、为什么没压"。
2. 运行日志：滚动上限 2 MiB × 2 份，只记判定结果与异常，不记任何消息正文。
3. A/B 对比：同题会话开/关插件，比首次压缩成功率、被拒率、总 token。

## 6. 风险与停止条件

- **最大的结构性风险**：摘要质量不可校验（验证要读原文，而读原文正是省下的钱）。缓解只有"压缩块必须比被压内容小"这一条硬约束 + 保留原文可取回。
- **依赖风险**：取回依赖「会话搜索」这个实验性插件；它没开时我们直接拒绝而不是降级。
- **升级风险**：我们只写宿主公开的四种事件，理论上跨版本稳定；但宿主改字段形状时不会通知我们，所以每条写入都在运行时校验、失败就响亮报错。
- **停止条件**（写进设计纪律）：任何功能，如果要做它就得"改写已经发出去的过去"、"在请求路径上重排过滤"、或者"维护一份跟表层并行、需要同步的私有状态"，那就一律不做——那正是这条赛道翻车的共同原因。
